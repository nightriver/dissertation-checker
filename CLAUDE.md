# Dissertation Checker — правила проекта

Streamlit-приложение для эксперта, который проверяет диссертации на плагиат и
академическую недобросовестность. Главная мишень — подделанный список
литературы. Приложение производит **доказательства** для экспертного висновку,
а не оценку.

## Активная работа

**План реализации — `PLAN_SEARCH.md` (режим `?mode=search`, ручной поиск
источников).** Порядок шагов — таблица **§22**.

Шаг выполняется не по плану напрямую, а по **пакету шага** `steps/step-NN.md`.
Пакет пишет оркестратор, читая план один раз. Дальше:

- `plan-implementer` / `plan-implementer-hard` — пишут код по пакету;
- `gate-writer` — пишет `tests/test_gate_step_NN.py` по пакету, **не видя
  кода**, параллельно с исполнителем;
- `plan-reviewer` — одно смысловое ревью.

**Сабагенты `PLAN_SEARCH.md` не открывают.** Если в пакете нет числа, есть
противоречие или два толкования — агент останавливается и возвращает вопрос
оркестратору. Не хватает пакета — это дефект пакета, а не повод читать план.

Цикл: `/plan-step N` — один шаг; `/plan-wave 4,5,12` — волна независимых
шагов параллельно. Таблица волн — в `PLAN_SEARCH_PROGRESS.md`.

**Стоимость меряется кругами доработки, а не токенами.** Один круг — три
холодных старта агентов. Пакет пишется так, чтобы второго круга не
понадобилось; лучше потратить время на пакет, чем на возврат.

Журнал:

- `PLAN_SEARCH_PROGRESS.md` — статус, волны и шесть строк на шаг. **Единственный
  источник правды о прогрессе**, читают все агенты. Короткий намеренно.
- `PLAN_SEARCH_JOURNAL.md` — хронология и расследования. Сабагенты не читают.

Прочие планы: `PLAN.md` (4 блока анализа списка литературы, реализован),
`PLAN_COMPARE_TWO_FILES.md` (сравнение двух файлов, отдельная работа),
`ROADMAP.md` (широкий контекст), `PLAN_SEARCH_COMPARE.md` — **АРХИВ, не читать
и не редактировать**.

Планы `PLAN_*.md` — контракт. Менять их можно только по прямому указанию
пользователя, никогда — «чтобы сошлось с кодом». То же касается
`steps/*.md`: их правит только оркестратор.

## Язык

- Код, UI-строки, docstrings, комментарии, README — **украинский**.
- **Имена тестовых функций — английский** (`test_every_scaffold_module_imports`),
  как во всём существующем наборе. Docstrings и комментарии внутри тестов
  остаются украинскими.
- `PLAN_*.md`, `steps/*.md`, `ROADMAP.md`, журналы, отчёты о работе — **русский**.
- Общение с пользователем — русский.

Русские буквы `ы э ъ ё` в docstrings и комментариях украинских модулей ловит
`tests/test_project_rules.py`. Если они там нужны как **данные** (алфавит для
определения языка, нормативное сокращение) — пометь строку `# ru-data`.

## Команды

```bat
.venv312\Scripts\python.exe -m pytest                            :: весь набор + coverage (порог 90 %)
.venv312\Scripts\python.exe -m pytest tests\test_x.py --no-cov   :: точечно во время работы
.venv312\Scripts\python.exe -m streamlit run app.py              :: приложение

# швидкий цикл без важкого корпусу
.venv312\Scripts\python.exe -m pytest --no-cov -m "not corpus"
.venv312\Scripts\python.exe -m pytest --no-cov -m corpus
```

Рабочее окружение — `.venv312` (Windows, `Scripts\python.exe`). `pytest.ini`
держит `--cov-fail-under=90`, поэтому **прогон подмножества тестов без
`--no-cov` падает по покрытию — это не регрессия**. Зелёным считается только
полный прогон без флагов.

Полный прогон за цикл делается **дважды**: исполнителем в конце работы и
ревьюером. Во время волны исполнители полный прогон не делают вообще — его
делает оркестратор один раз на сведении волны.

## Механические правила проверяет `tests/test_project_rules.py`

Он ловит: `get_text("blocks")`, `pymorphy3` в `search/`, недетерминизм
(`datetime.now()`, `date.today()`, `random`, `uuid`), LLM-зависимости,
`skip`/`xfail` в наборе, понижение `--cov-fail-under`, отсутствие ссылки на
план в docstring модуля `search/`, русские буквы в украинской прозе, изменение
публичного интерфейса `parser/*`.

**Добавляешь жёсткое правило сюда — добавляй туда тест.** Правило, которое
проверяет только ревьюер, будет заново выводиться на каждом шаге и рано или
поздно пропустится.

## Жёсткие правила предметной области

1. **LLM в продукте запрещены.** Только детерминированные правила: результат
   должен быть воспроизводим и защитим в спецсовете. Это ограничение заказчика.
2. **Режим поиска — последний шанс после Plag и Strike.** Приоритет обратный
   обычному: **recall важнее precision**. Ложный запрос стоит одного клика,
   пропущенный источник — незамеченного плагиата. Порог precision ≥90 %
   относится только к tier 1 в отчёте эксперта, не к отбору запросов.
3. **Ничего не подавляется молча.** Отфильтрованный кандидат остаётся в
   диагностических счётчиках с причиной отсева. Счётчики видны всегда,
   включая нулевые.
4. **Не строить блоки PDF через `get_text("blocks")`** — брать `dict` и
   восстанавливать абзацы. Существующий `_extract_paragraphs_pdf` отказался от
   `blocks` сознательно, об этом написано в его docstring.
5. **Печатный номер страницы в режиме поиска не восстанавливается.** Только
   честное «аркуш PDF N» плюс копируемый устойчивый фрагмент для `Ctrl+F`.
   `PageRef` и ручная калибровка сюда не возвращаются.
6. **Запросы строятся из словоформ, а не из лемм.** `pymorphy3` в режиме
   поиска не используется.
7. **`find_content_bounds_in_texts` не переиспользовать для зон** — он
   выбрасывает ВСТУП и ВИСНОВКИ, а «Наукова новизна» это подраздел ВСТУПУ.
   Зоны делит `split_zones` (body / bibliography / after).
8. **Пороги — это числа в плане.** «Слишком частый», «небольшой разрыв» без
   числа невоспроизводимы ни в коде, ни в тестах. Число берётся из раздела
   «Числа» пакета шага; если его там нет — остановиться и спросить, а не
   придумывать.
9. **Никаких «процент честности», «вероятность заимствования», «выявляет
   перефразирование».** Каждая находка несёт уровень доверия: 🔴 PROOF /
   🟡 SUSPECT, рядом всегда сырой текст.
10. **Состояние триажа не живёт в `st.session_state`** — JSON-проект с хешем
    файла и стабильными id (хеш координат, не порядковый номер).
11. Разрешённые внешние API: Crossref, OpenAlex, doi.org, Web Archive.
    Яндекс — только ссылка в браузер, API нет.

## Границы правок

- Не рефакторить чужие модули «заодно». Шаг — ровно шаг пакета.
- Не менять публичные интерфейсы `parser/*` без явного указания: от них
  зависят основной режим и режим сравнения.
- Существующий код не копируется в `search/`: адаптеры переиспользуют
  `parser.types.is_toc_entry`, `parser.types.MAX_SOURCE_NUM`,
  `parser.citations.BRACKET_RE`, `expand_bracket`,
  `parser.bibliography.split_zones` и `parse_bibliography`.
- Не трогать `.venv`, `.venv312`, `examples/`, `tmp/`.
- Фикстуру `tests/fixtures/search_corpus_expectations.json` алгоритм
  перезаписывать не может: это ручные наблюдения, а не снимок вывода.
- `tests/test_gate_step_NN.py` исполнитель не редактирует. Спор со шлюзом
  решается через оркестратора: файл, строка, пункт пакета, в чём расхождение.
- Никаких `git push`. Коммиты делает оркестратор.
