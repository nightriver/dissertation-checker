Прочитай `PLAN_SEARCH_PROGRESS.md` и строку шага в §22 `PLAN_SEARCH.md`
(`sed -n '1689,1720p' PLAN_SEARCH.md`), затем секции плана, на которые она

Если шаг зависит от решения, которого в плане нет (нет числа, противоречие,
два толкования) — **останови цикл и спроси меня**. Не выбирай за план.

## 2. Реализация

Вызови `plan-implementer` **одним сообщением с полным ТЗ**. Сабагент не видит
наш диалог: перескажи ему всё, включая номера секций плана и пороги. Не пиши
«как обсуждали выше».

## 3. Тесты

Вызови `test-runner`. Красное — назад к `plan-implementer` с дословным
traceback.

## 4. Ревью

Вызови `plan-reviewer` с номером шага и списком изменённых файлов.
Блокирующие замечания — назад к `plan-implementer`.

**Максимум два круга правок.** Если после второго круга есть блокирующее —
остановись, покажи мне суть спора и жди решения. Не начинай третий круг сам.

## 5. Журнал и остановка

Обнови `PLAN_SEARCH_PROGRESS.md`: статус шага, дата, файлы, итог тестов и
покрытие, принятые решения, незакрытые замечания, вопросы к плану.

Сделай коммит: `git add -A && git commit -m "search: шаг N — <суть>"`.
Без `git push`.

Покажи мне сводку на 10–15 строк и **остановись**. К следующему шагу не
переходи, пока я не подтвержу.
