## 0. Проверь, что шаги правда независимы

Волна законна, только если списки «Файлы шага» у её шагов **не пересекаются**
и ни один шаг волны не импортирует то, что пишет другой шаг той же волны.
Пересеклись — вынеси шаг в следующую волну. Интеграция на стыке съедает
выигрыш от параллелизма, это уже проверено на шаге 3.

## 1. Пакеты

Напиши `steps/step-NN.md` для каждого шага волны — по разделам из
`/plan-step`, шаг 1. Это единственное место, где читается `PLAN_SEARCH.md`.
В разделе «Файлы шага» каждого пакета явно перечисли файлы **других шагов
волны** под заголовком «не трогать: их пишет параллельный агент».

## 2. Запуск — все агенты одним сообщением

В одном сообщении вызови для каждого шага волны пару:
`gate-writer` + исполнитель (`plan-implementer`, либо
`plan-implementer-hard` для шагов 5, 8, 16). Для волны из трёх шагов это
шесть агентов в одном сообщении.

**Скажи каждому исполнителю: полный прогон `pytest` не делать.** Только
точечно с `--no-cov` по своему шлюзу и своим тестам. Пока волна не сошлась,
покрытие ниже порога — это нормально, и падение общего прогона у одного
агента заставит его чинить чужой шаг.

## 3. Сведение волны

1. Собери отчёты. Красный шлюз — верни соответствующему исполнителю
   дословный текст падения.
2. Когда все точечные зелёные — **ты** делаешь один полный прогон:
   `.venv312\Scripts\python.exe -m pytest`.
3. Падение на стыке двух шагов волны — верни обоим исполнителям **одно и то
   же** сообщение с трассировкой и явным «кто чей файл правит».

## 4. Ревью — тоже параллельно

`plan-reviewer` только читает, поэтому N ревьюеров запускаются одним
сообщением без конфликтов. Каждому — свой номер шага и свой пакет. Скажи
им, что полный прогон уже сделан тобой, и приложи его итог: пусть каждый
прогонит только `tests\test_gate_step_NN.py --no-cov`, а полный — лишь если
после ревью менялся код.

**Максимум один круг правок на волну.**

## 5. Журнал и коммиты

Коммиты — по одному на шаг, последовательно:
`git add <файлы шага> && git commit -m "search: крок N — <суть>"`.
Так история остаётся читаемой, даже если шаги делались параллельно.

В `PLAN_SEARCH_PROGRESS.md`: `✔` в таблице и запись до шести строк на каждый
шаг. Списки «сделано вперёд» из отчётов ревью перенеси обязательно.
