# Дорожня карта — розширення перевірок

Документ описує, які нові перевірки додаються до застосунку, за яким правилом
кожна працює, і де в неї межа достовірності.

**Рамки, узгоджені з замовником:**

* зовнішні API дозволені (Crossref, OpenAlex, doi.org, Web Archive);
* LLM **не використовуються** — тільки детерміновані правила, щоб результат
  був відтворюваним і його можна було захистити у спецраді;
* пріоритети: фабрикація списку літератури → запозичення тексту без
  посилань → швидкість роботи експерта;
* експорт звіту поки не потрібен.

**Наскрізний принцип.** Жодна перевірка не виносить вирок. Кожна знахідка
має рівень довіри й показує сирий текст запису, щоб експерт бачив підставу:

| Рівень | Значення | Приклад |
|---|---|---|
| 🔴 `PROOF` | Технічно неможливо або математично хибно | Рік видання пізніший за рік захисту; ISBN не проходить контрольну цифру |
| 🟡 `SUSPECT` | Сильна аномалія, потребує погляду людини | Дубль запису; 40 сиріт поспіль; цитата в лапках без посилання |
| ⚪ `UNKNOWN` | Перевірити не вдалося — **не** ознака порушення | Українська монографія, якої немає в Crossref |

Змішувати `UNKNOWN` із `SUSPECT` не можна: більшість української наукової
періодики та монографій не індексується міжнародними базами, і «не знайдено»
там нічого не доводить.

## Спринт 1 — офлайн, без мережі

Найдешевші перевірки з найбільшою віддачею. Усі дані вже є в застосунку.

### 1.1 Анахронізм — джерело новіше за дисертацію

**Модуль:** `parser/anomalies.py`

```python
def find_anachronisms(
    years: dict[int, int | None],
    dissertation_year: int | None,
) -> dict[int, str]:
    """{номер: причина} для джерел, які не могли існувати на момент захисту."""
```

Правило:

* `year > dissertation_year` → 🔴 `PROOF`;
* `year > поточний_рік` → 🔴 `PROOF` незалежно від року дисертації;
* `year > dissertation_year - 1` при відсутності року дисертації → пропуск.

Усе необхідне вже є: `extract_years()` і `extract_dissertation_year()`.
Зараз рік дисертації лише малюється пунктиром на графіку — жодна метрика
його не використовує.

**Ризик хибних спрацювань:** `extract_year()` може підхопити не рік видання,
а число з ISBN, обсягу чи номера журналу. Тому в таблиці обов'язково
показувати повний текст запису й підсвічувати саме той фрагмент, з якого
взято рік.

### 1.2 Дублікати й майже-дублікати в списку

**Модуль:** `parser/duplicates.py`

```python
def find_duplicates(
    bibliography: dict[int, str],
    threshold: float = 0.85,
) -> list[tuple[int, int, float]]:
    """Пари номерів, які описують одне й те саме джерело, + схожість."""
```

Алгоритм:

1. Нормалізація: нижній регістр, зняття пунктуації й розділювачів ДСТУ
   (` : `, ` // `, ` / `, ` . – `), стиснення пробілів.
2. Виділення *назви* — сегмент до першого ` / ` або ` // ` (за ДСТУ саме там
   закінчується назва). Порівнюємо назви, а не цілі рядки: інакше дві різні
   статті одного автора в одному журналі дадуть хибний збіг.
3. Точний збіг нормалізованої назви → 🟡 `SUSPECT`, підпис «точний дубль».
4. `difflib.SequenceMatcher.ratio() >= threshold` **і** збіг року → 🟡
   `SUSPECT`, підпис «майже дубль».

`difflib` — стандартна бібліотека, нових залежностей не треба. Складність
O(n²); при n ≤ 500 це 125 тис. порівнянь, десяті частки секунди.

**Навіщо.** Дубль під двома номерами — типовий спосіб добити список до
нормативних 200 позицій, не читаючи нічого нового.

### 1.3 Контрольні цифри ISBN / ISSN, формат DOI

**Модуль:** `parser/identifiers.py`

```python
def extract_identifiers(entry: str) -> dict[str, list[str]]:
    """{'isbn': [...], 'issn': [...], 'doi': [...], 'url': [...]}"""

def validate_identifiers(entry: str) -> list[tuple[str, str, bool]]:
    """[(тип, значення, чи_валідне)] — офлайн-перевірка контрольних цифр."""
```

* **ISBN-10** — `sum(d[i] * (10 - i)) mod 11 == 0`, останній символ `X` = 10.
* **ISBN-13** — EAN-13: `sum(d[i] * (1 або 3)) mod 10 == 0`.
* **ISSN** — mod-11 з контрольною цифрою, `X` допустимий.
* **DOI** — тільки формат: `10\.\d{4,9}/[-._;()/:\w]+`. Існування — у спринті 2.

ISBN, який не проходить контрольну цифру, — 🔴 `PROOF`: вигаданий номер
майже завжди провалює checksum, а ймовірність, що людина зробила саме таку
одиночну помилку набору, мала. Все одно варто позначати як «недійсний ISBN»,
а не «підробка», бо одруківка теоретично можлива.

### 1.4 Суцільні блоки сиріт

**Модуль:** `parser/orphan_runs.py`

```python
def orphan_runs(orphans: set[int]) -> list[tuple[int, int]]:
    """Суцільні прогони не згаданих джерел: [(15, 54), (120, 122), ...]"""

def orphan_density_profile(
    all_sources: set[int],
    orphans: set[int],
    buckets: int = 10,
) -> list[float]:
    """Частка сиріт у кожній десятій частині списку."""
```

Зараз сироти показуються плоским рядком номерів. Але 40 номерів **поспіль**
без жодної згадки — це не забудькуватість, це вставлений шматок чужої
бібліографії. Прогон довжиною ≥ 10 → 🟡 `SUSPECT` окремим рядком.

Профіль щільності відповідає на інше питання: якщо перші 60 % списку
використані, а останні 40 % — суцільні сироти, список нарощували в кінці.

Обидві функції — чиста арифметика над уже наявним `result["orphans"]`.

### 1.5 Цитати в лапках без посилання

**Модуль:** `parser/quotes.py`

```python
def find_uncited_quotes(
    lines: list[LineItem],
    min_words: int = 5,
    lookahead_chars: int = 120,
) -> list[dict]:
    """Прямі цитати, поруч з якими немає жодного посилання [N]."""
```

Правило:

1. Знаходимо вміст лапок: `«…»`, `„…“`, `"…"`.
2. Відкидаємо короткі — менше `min_words` слів. Це відсіює терміни в лапках
   («джерело», «недоброчесність») і назви установ.
3. Після закривальної лапки шукаємо `BRACKET_RE` у межах `lookahead_chars`
   і **до кінця речення**. Використовуємо `BRACKET_RE` та `expand_bracket()`
   з `parser/citations.py` — щоб «цитата [2020]» не зарахувалася.
4. Немає валідного посилання → 🟡 `SUSPECT`.

Зона пошуку — та сама, що і в `paragraph_analyzer`: змістовні розділи без
вступу, змісту, анотації, висновків і бібліографії.

**Чому це важливо.** Пряма цитата без атрибуції — це буквально означення
плагіату, а не привід «подивитися уважніше». З усіх перевірок офлайн-групи
ця дає найчистіший доказ.

## Спринт 2 — онлайн-верифікація існування джерел

Ядро задачі про підроблений список. Мережа дозволена, ключі не потрібні.

### 2.1 Архітектура

**Модуль:** `parser/verify_online.py`

```python
@dataclass
class VerificationResult:
    num: int
    status: Literal["found", "not_found", "unchecked"]
    source: str | None          # "doi.org" | "crossref" | "openalex"
    matched_title: str | None   # що саме знайшлося
    mismatches: list[str]       # ["рік: у списку 2019, у Crossref 2017"]

def verify_bibliography(
    bibliography: dict[int, str],
    only: set[int] | None = None,
    concurrency: int = 5,
) -> dict[int, VerificationResult]:
```

Порядок перевірки одного запису:

1. **DOI є в записі** → `GET https://doi.org/api/handles/{doi}`.
   Відповідь `responseCode: 1` = ідентифікатор існує. Це найшвидша й
   найдешевша відповідь, без парсингу метаданих.
2. **DOI резолвиться** → `GET https://api.crossref.org/works/{doi}` і
   звірка метаданих (див. 2.2).
3. **DOI немає, запис латиницею** → `GET https://api.crossref.org/works`
   з `query.bibliographic=<нормалізований запис>&rows=1`. Crossref повертає
   поле `score`; поріг підбираємо емпірично на `examples/`, орієнтовно
   `score >= 60` разом зі збігом року.
4. **Нічого не знайшлося в Crossref** → `https://api.openalex.org/works`
   з `search=`. OpenAlex ширший за Crossref і покриває частину видань без DOI.
5. **Запис кирилицею без DOI** → статус `unchecked`. Українські монографії,
   збірники й автореферати в цих базах здебільшого відсутні, і «не знайдено»
   там нічого не означає.

**Ввічливість до API.** Обидва сервіси просять `mailto` у User-Agent —
за це дають вищий пріоритет (polite pool). Ставимо
`User-Agent: dissertation-checker/1.0 (mailto: <адреса>)` і виносимо адресу
в `st.secrets`.

---

### 2.2 Розходження метаданих — підпис зібраного запису

Найсильніший детермінований сигнал фабрикації. Якщо DOI **існує**, але
метадані Crossref не збігаються з тим, що написано в списку:

| Що порівнюємо | Правило розходження |
|---|---|
| Рік | різниця ≥ 2 роки |
| Прізвище першого автора | не входить у рядок запису (з урахуванням транслітерації) |
| Назва | `SequenceMatcher.ratio() < 0.6` до нормалізованих назв |

Два й більше розходжень → 🔴 `PROOF`: реальний DOI, підставлений до чужої
назви й авторів. Саме так виглядає посилання, зібране з правдоподібних
шматків, а не переписане з реальної роботи.

---

### 2.3 Мертві URL і «дата звернення»

Записи з `URL :` та `дата звернення` за ДСТУ:

* `HEAD` запит з таймаутом 5 с → 🟡 `SUSPECT` при 404/410;
* якщо ресурс мертвий, питаємо Web Archive:
  `https://archive.org/wayback/available?url=<url>&timestamp=<дата_звернення>`.
  Знімка немає **на заявлену дату** → 🟡 `SUSPECT`, бо автор стверджує, що
  бачив сторінку саме тоді.

---

### 2.4 UX онлайн-перевірки

Це найповільніша частина застосунку, тому:

* **Режим «тільки сироти» за замовчуванням.** Сироти — і найпідозріліші, і
  їх у рази менше. 250 джерел перевіряються 1–2 хв, 40 сиріт — секунд 15.
* `st.progress` з номером поточного джерела; кнопка «Зупинити».
* Кеш по хешу нормалізованого запису через `@st.cache_data` — повторний
  запуск на тому самому файлі миттєвий.
* Конкурентність 5 через `concurrent.futures.ThreadPoolExecutor`; більше не
  треба — обидва API це помітять.
* Мережа може бути недоступна. Будь-яка помилка запиту → `unchecked`,
  ніколи не `not_found`. Вкладка має лишатися робочою офлайн.

## Спринт 3 — форензика документа

Перевірки, яких немає в комерційних сервісах перевірки на плагіат. Усі
офлайн і швидкі.

### 3.1 Гомогліфи та невидимі символи

**Модуль:** `parser/text_forensics.py`

```python
def find_homoglyphs(lines: list[LineItem]) -> list[dict]:
def find_invisible_chars(lines: list[LineItem]) -> dict[str, list[int]]:
```

**Гомогліфи.** Класичний спосіб обійти пошук збігів: у переважно
кириличному слові кілька літер замінено на латинські двійники —
`а е о с р х у А В Е К М Н О Р С Т Х`. Візуально текст не змінюється,
а збіг із джерелом не знаходиться.

Правило проти хибних спрацювань: слово підозріле, якщо воно
**на ≥ 60 % кириличне** і містить 1–3 латинські літери **з набору
гомогліфів**. Це не чіпає легітимні `IT-технології`, `e-mail`, `COVID-19`,
де латиниця становить більшість або не є двійником.

Одне-два слова — випадковість розкладки. Десятки — 🔴 `PROOF`: випадково
так не виходить.

**Невидимі символи.** `U+200B` (ZWSP), `U+200C/200D`, `U+00AD` (м'який
перенос), `U+FEFF`, `U+2060`. Вставлені всередину слів, вони розривають
слово для пошуковика, лишаючи його цілим на вигляд. Рахуємо кількість,
частку уражених слів і сторінки.

---

### 3.2 Прихований текст

**Модуль:** `parser/hidden_text.py`

**PDF** — через `page.get_texttrace()`, який віддає режим рендерингу
кожного спану: `type == 3` — текст невидимий (класичне «набивання»
ключовими словами). Додатково через `page.get_text("dict")`:
`span["color"] == 16777215` (білий) і `span["size"] < 2`.

**DOCX** — на рівні `w:rPr`:

* `<w:vanish/>` — прихований текст;
* `<w:color w:val="FFFFFF"/>` — білий на білому;
* `<w:sz w:val="2"/>` — кегль 1 pt.

Будь-яке з цього в обсязі понад кілька символів → 🔴 `PROOF`. У
доброчесній роботі прихованого тексту не буває.

---

### 3.3 Метадані документа

**Модуль:** `parser/doc_metadata.py`

**DOCX** — `core.xml` через `doc.core_properties` і `app.xml`:

| Поле | Ознака |
|---|---|
| `author` / `last_modified_by` | Не збігається з ПІБ на титулці → 🟡 |
| `revision` | ≤ 5 при обсязі 150+ сторінок → 🟡 |
| `TotalTime` (хв) | Десятки хвилин на всю дисертацію → 🟡 |
| `created` | Пізніше за рік на титулці → 🟡 |
| `modified < created` | Дати правлені вручну → 🔴 |
| `Company` / `Application` | Сторонні — напр. слід конвертера чи чужої організації |

`extract_dissertation_author()` для звірки вже написаний.

**PDF** — `doc.metadata`: `producer`, `creator`, `creationDate`, `modDate`.
Плюс непрямий сигнал склейки: набір шрифтів по сторінках
(`page.get_fonts()`). Різкі зміни набору шрифтів між сторінками означають,
що сторінки прийшли з різних документів.

**Аналіз `rsid` (DOCX)** — окремо, як найважча частина. Word проставляє
revision save ID кожному запуску правок; великий блок тексту з `rsid`, який
більше ніде в документі не зустрічається, — вставка з іншого файлу. Дає
буквально карту вставленого. Виносити в кінець спринту.

---

### 3.4 Стилометрія — зсув авторства всередині роботи

**Модуль:** `parser/stylometry.py`

Детермінована статистика, без моделей. Вікно — 10 послідовних абзаців
із тих, що вже витягує `paragraph_analyzer.extract_paragraphs()`:

* середня довжина речення та її стандартне відхилення;
* середня довжина слова;
* type-token ratio (лексична різноманітність);
* щільність пунктуації;
* частка службових слів.

Рахуємо z-оцінку кожної метрики відносно медіани по документу. Вікно,
де ≥ 3 метрики виходять за `|z| > 2.5`, → 🟡 `SUSPECT`: цей фрагмент писала
інша рука.

**Ризик хибних спрацювань високий.** Формули, таблиці, переліки й цитати
природно ламають статистику. Тому фільтруємо абзаци так само, як це вже
робить `paragraph_analyzer` (`MIN_BLOCK_CHARS`, наявність літер), і подаємо
результат як графік уздовж документа, а не як звинувачення.

## Спринт 4 — швидкість роботи експерта

### 4.1 Зведений екран ризику

Зараз, щоб побачити картину, треба обійти дві вкладки й розгорнути кілька
`expander`. Замість цього — перший екран із 6 світлофорів, кожен веде до
своєї деталізації:

| Сигнал | Джерело |
|---|---|
| Неможливі джерела | 1.1 + 1.3 |
| Список не використовується | сироти + 1.4 |
| Джерела не існують | 2.1 + 2.2 |
| Цитати без атрибуції | 1.5 |
| Обхід антиплагіату | 3.1 + 3.2 |
| Питання до метаданих | 3.3 |

Загального «відсотка доброчесності» не робимо: одне число ховає підставу
й провокує механічний вирок. Світлофор із переходом до доказу — робить
навпаки.

### 4.2 Реорганізація вкладок

Двох вкладок стане замало. Пропозиція: `Огляд` · `Список літератури` ·
`Текст` · `Документ`.

---

## Технічний борг, помічений при рев'ю

1. `render_tab_checker(zone_result, file_bytes, filename, …)` — `file_bytes`
   і `filename` всередині не використовуються.
2. `st.session_state["zone_result"]` записується, але ніде не читається.
3. `_select_biblio_header()` викликає `parse_bibliography()` для **кожного**
   кандидата на необмеженій зоні. Коли заголовок повторюється колонтитулом
   на 40 сторінках бібліографії — це 40 повних парсингів хвоста документа.
   Варіанти: обмежити довжину зони під час оцінювання або мемоїзувати.
4. `extract_years()` і `validate_bibliography()` рахуються заново на кожному
   ререндері Streamlit — на відміну від `cached_analyze()`.
5. `_ANCHOR_CITY_YEAR` вимагає місто й рік **в одному рядку**. На титульних
   сторінках PDF «Київ» і «2023» майже завжди два окремі рядки, тож працює
   запасний прохід `max()`, який може підхопити рік із УДК чи з назви закону.
   Варто дивитися на 1–2 рядки вперед від назви міста.
6. `highlight_citations_pdf()` — `doc.tobytes(deflate=True)` тримає другу
   копію документа в пам'яті. На 1 ГБ Streamlit Cloud із 30 МБ PDF це
   головний кандидат на OOM; варто додати `garbage=3`.

---

## Що свідомо не робимо

* **Семантичне зіставлення «контекст посилання ↔ назва джерела».** Найсильніший
  сигнал проти номерів, розставлених навмання, але без LLM він не працює
  надійно, а LLM виключено умовами.
* **Тематична релевантність джерела темі роботи.** Те саме обмеження.
  Груба лексична версія (перетин слів назви джерела із заголовками розділів)
  дає забагато хибних спрацювань, щоб її показувати експертові.
* **Власна база текстів для пошуку збігів.** Це вже інший продукт; збіги
  шукають Unicheck і StrikePlagiarism, а цей застосунок закриває те, чого
  вони не бачать.
